## 1. 证据与判定纪律

- 仅使用巨潮资讯网可访问的公司年报、半年报或公司公告作为点锚；没有用公司官网社媒、媒体转载或券商研报作 point 锚。
- 每条 point 保留主体、`cell_id`、`product_family`、能力角色、范围、成熟度、短引、URL、检索日、T1 层级和待人工裁决事项。
- 年报中出现“集团”“子公司”“客户”“产品应用”不自动把能力归给另一主体；上市发行人、法人、厂址、集团仍需单独映射。
- “具备能力”“建成产线”“研发/认证”“量产”分别保留语义。候选中 `mass_production` 仅表示来源明确出现生产/销售/量产语句，不代表本项目已确认具体厂址或全部产品量产。
- 没有完整 `capacity_owner / process_operator / contracting_party / product_integrator / seller_of_record` 五元组的关系不写 `manufacturing_edge`。

## 4. Manufacturing edge 审核结果

本轮 **不创建任何 `manufacturing_edge`**。

原因是目前一手材料虽出现以下关系线索，但均缺少 DP5 要求的完整五元组：

1. 生益电子年报披露向生益科技采购覆铜板、半固化片等原材料：这是可继续核验的关联采购/供应关系，不是制造委外关系；没有 `capacity_owner`、`process_operator`、`contracting_party`、`product_integrator`、`seller_of_record` 的完整关系声明。
2. 东威科技年报披露“与公司合作的外协厂商”及外协工艺：没有公开列出具体外协主体和五元组角色，不能据此创建表面处理或委外加工边。
3. 大族数控、东威科技、芯碁微装的“销售/服务/客户”语句只能支持设备供应能力点，不能推出设备安装方、产能所有者或裸板生产关系。

因此 `data/candidates/company_points_edges.json` 的 `manufacturing_edges` 保持空数组。后续若取得完整五元组，必须新建独立 edge，不能从这些 point 反推。

## 6. JSON schema 差异与导入说明

`data/candidates/company_points_edges.json` 以 `packages/dp5-ledger/fixtures/valid_ledger.json` 的根结构、主体映射、point、edge 和禁止加总 pair 字段为骨架。为满足候选审计需要，本轮在主体/point/pair 上增加了：

- `subject_name`
- `source_url`
- `retrieval_date`
- `t1_level`
- `review_status`（本轮全部为 `pending`）
- `manual_adjudication`
- `source_locator`（部分 point）

这些扩展字段使候选 JSON **不能直接通过 DP5 的 exact-key 校验**；这是有意的 fail-closed 设计。主线程导入前应先保留本文件作为可追溯副本，再由人工裁决映射/挂格/成熟度后剥离扩展字段或转换为正式账本。报告表格和本 JSON 逐条对应，未把候选升级为 canonical。

## 7. 检索轨迹与停止条件

- 轨迹：按主体+年报/公告+产品关键词检索巨潮；对已找到的 PDF 使用全文定位核对主体、产品、工序和成熟度短引；同一 PDF 的多个点共用同一 T1 文档，但每条 point 单独保留锚 ID。
- 本轮停止于“每个 L1-A/B/C 至少 3 家代表性 A 股主体且每条 point 有四件套锚点”。未将二手转载、公司官网产品页、社媒、市场份额或泛行业预测转成点。
- 重新开放条件：取得具体法人/厂址/产线证据；取得产品族拆分证据；取得客户/设备安装或委外关系的完整五元组；人闸批准 T1 承重与正式分母层级。
